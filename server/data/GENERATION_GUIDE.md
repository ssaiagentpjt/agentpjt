# 목업 상품 데이터 생성 지침 (약 3,000개, 대분류별 분담, 옵션 포함)

이 문서는 **상품 데이터를 만드는 세션**에게 주는 작업 지시서다. 이 문서와 저장소의 `server/` 폴더만 보고
맡은 대분류의 데이터를 만들고 검사까지 통과시킬 수 있어야 한다.
모르는 것이 있으면 추측하지 말고 작업을 멈춘 뒤 사용자에게 묻는다.

> 개정 2026-10-05: 상품 옵션(색상·사이즈·도수·맛), 태그 6개 이상, 목표 수 약 3,000개(소분류 최소 8개), 브랜드 풀 확대.
> 이전 지침으로 만든 파일이 있으면 3절의 **보강 절차**를 따른다.

---

## 1. 이 데이터가 쓰이는 곳

- **앱**: 노인(70대 이상)용 음성 쇼핑 앱 "말로장보기"(가칭). 어르신이 말로 원하는 것을 이야기한다.
- **검색하는 쪽**: 앱 안의 온디바이스 LLM(Gemma)이다. 모델이 짧은 검색어와 조건을 만들어
  이 서버의 `GET /products/search`를 부른다.
  - 예: "무릎이 쑤셔서 붙이는 거, 너무 비싸지 않은 걸로" → `q=무릎 파스&priceTier=low`
  - 예: "손주 선물로 뭐가 좋을까" → `q=선물&audience=kids&gift=true`
  - 예: "검정색 장갑" → `q=검정 장갑`
- **검색 방식**: 검색어를 공백으로 나눈 **낱말마다** 상품명·태그·분류 이름·브랜드·옵션값에 그 낱말이 **부분 문자열로** 들어 있는지 본다(`app/search.py`).
  - 가중치: 상품명 3, 태그 2, 소분류명 2, 중분류명 1, 대분류명 1, 브랜드 1, 옵션값 1
  - 낱말이 태그 하나와 **정확히 같으면** +1을 더 준다.
  - 검색어의 **모든 낱말이 맞으면** +4를 더 준다.

  그래서 **태그가 검색 품질을 거의 결정한다.**
- **옵션과 되묻기**: 옵션이 있는 상품을 주문할 때 옵션을 고르지 않으면, 서버가 "사이즈를 골라야 한다: M, L, XL"을 돌려준다.
  앱의 모델은 이것을 보고 어르신께 되묻는다("어떤 사이즈로 드릴까요?"). 그래서 **옵션 이름과 값은 소리 내어 읽기 쉬워야 한다.**
- **모델이 판단에 쓰는 지표**: 가격대 등급, 판매 순위, 할인율, 단위 가격, 재구매율, 평점, 대상(audience), 선물용 여부.
  이 중 **순위·등급·할인율·단위 가격·배지는 서버가 계산한다.** 데이터에는 계산의 재료가 되는 입력값만 쓴다.
- **성격**: 온라인 종합몰(쿠팡·지마켓형)을 흉내 낸 **가상 데이터**다. 실제 상품·실제 가격을 흉내 내지 않는다.

## 3. 작업 순서

### 기존 파일이 있으면: 보강 절차 (먼저 한다)
이전 지침으로 만든 파일(예: beauty 111개)이나 처음부터 있던 28개는 버리지 않고 고쳐 쓴다.
1. `python -m app.validate --main <id>`를 돌려 오류를 본다. 대부분 "tags 는 6개 이상"이다.
2. 레코드마다 다음을 한다.
   - **태그 보강:** 6~10개가 되게 7절 규칙대로 채운다.
   - **옵션 추가:** 4절 기준에 맞는 상품에 붙인다.
     - 이름·규격에 들어 있던 옵션값은 이름에서 뺀다. 예: "거품형 염색약 흑색" + 색상 옵션(흑색·자연갈색·밝은갈색)
     - 옵션으로 합친 상품의 다른 레코드는 지우거나 다른 품목으로 바꾼다.
     - 이미 쓴 id는 다시 쓰지 않는다.
3. 새 목표(`target`)까지 상품을 더한다. id는 그 파일의 마지막 번호에서 이어 매긴다.
4. 아래 일반 순서의 4번부터 이어간다.

### 일반 순서 (대분류마다)
1. 다음을 읽는다.
   - `app/models.py`: `ProductSeed`, `OptionAxisSeed`, `MainSeed`
   - `categories.json`에서 맡은 대분류: 중분류·소분류·`target`·`priceRange`·`brands`·`idPrefix`
   - `app/validate.py`
   - `products/medical.json`, `products/silver.json`: 옵션 예시가 있다
2. **기획표**를 만든다. 대화에만 두고 파일로 저장하지 않는다.
   - 소분류마다 `target`개의 품목 목록(품목 종류, 규격, 가격, 브랜드, 옵션 여부)
   - 중분류마다 인기 순서
3. **중분류 단위로** 레코드를 생성해 파일에 덧붙인다. 한 줄에 레코드 하나씩 쓴다.
4. `python -m app.validate --main <id>`로 검사한다. **오류 0건**이 될 때까지 고친다.
5. 경고를 줄인다. 목표는 **경고 0건**이다.
   - 대상: 가격대 밖, 목표 미달, 브랜드 쏠림, 거의 같은 이름, 짧은 핵심어 없음
   - 규격 변형의 `이름이 거의 같다` 경고는 남아도 된다.
6. 검사 출력의 달성률·상위3 판매 비중·분포·옵션 비율을 읽고, 사람이 봐도 그럴듯한지 확인한다.
7. 12절 형식으로 보고한다.

## 4. 옵션 (`options`)

**옵션으로 묶는 것:** 같은 상품에서 **고르기만 하는 차이.** 색상, 사이즈, 돋보기 도수, 맛, 향, 신발 치수 등.
**별개 상품으로 두는 것:** 규격·가격이 크게 다른 것. 쌀 4kg / 10kg, 두유 24팩 / 48팩, 2인용 / 4인용 냄비 등.

```json
"options": [
  {"name": "사이즈", "values": [
    {"value": "M"}, {"value": "L"}, {"value": "XL", "priceAdd": 2000, "stock": "low"}]},
  {"name": "색상", "values": [{"value": "회색"}, {"value": "남색"}]}
]
```

| 규칙 | 내용 |
|---|---|
| 축 개수 | 0~2개. 옵션이 없으면 `options`를 빼거나 `[]` |
| 값 개수 | 축마다 2~6개, 중복 금지 |
| 축 이름 | 짧고 소리 내어 읽기 쉽게: 색상, 사이즈, 도수, 맛, 향, 용량, 치수 |
| 값 | 1~20자. 어르신이 말로 고를 수 있게: "검정", "갈색", "M", "L", "+2.0", "235", "고소한 맛". 영어 색 이름("BLACK")은 쓰지 않는다 |
| `priceAdd` | 그 값을 고르면 더하는 금액. 0(기본)~가격의 50%, 10원 단위. 큰 사이즈·고급 맛 등에만 |
| `stock` | 값별 재고(in_stock / low / sold_out). 없으면 상품 재고를 따른다. 옵션 상품의 약 20%에 low 또는 sold_out 값을 하나 둔다. **모든 값이 품절이면 안 된다** |

**대분류별 옵션 상품 비율** (전체 약 30%)
| 대분류 | 비율 | 흔한 축 |
|---|---|---|
| fashion, fashion-acc | 70~90% | 사이즈, 색상, 치수 |
| sports, interior | 40~60% | 사이즈, 색상 |
| silver, hygiene, kids | 30~50% | 사이즈(보호대·기저귀), 색상(지팡이·완구) |
| beauty, pet | 20~40% | 색상(염색약 호수), 향, 맛 |
| kitchen, medical, digital | 15~30% | 색상, 도수(돋보기), 사이즈 |
| health-food, food, living, hobby | 5~20% | 맛, 향 |

옵션이 있는 상품은 이름에 옵션값을 넣지 않는다. 예: "무릎 보호대 2개입 L"이 아니라 "무릎 보호대 2개입" + 사이즈 옵션.

## 5. 분류·브랜드·가격대·id

- `category`는 `{"main": 대분류 id, "mid": 중분류 id, "sub": 소분류 id}`. 세 단계가 `categories.json` 트리와 정확히 맞아야 한다.
- **소분류마다 `target`개**를 만든다. ±1~2개는 괜찮다. 70% 미만이면 경고, 0개면 오류다.
- **id**: `p` + 대분류 `idPrefix` 2자리 + 일련번호 3자리. 예: `p02007`.
  대분류 안에서 001부터 증가시킨다. 기존 상품의 id는 그대로 두고 이어 매긴다. 지운 레코드의 id는 다시 쓰지 않는다.
- **brand**: 그 대분류 `brands` 풀(14~18개)에서만 고른다. 풀 밖이면 오류, 한 브랜드가 20%를 넘으면 경고다.
- **price**: 중분류 `priceRange` 안에서 정하고, 중분류 안에서 싼 것·중간·비싼 것이 고르게 있게 한다. 서버가 중분류 안 백분위로 등급을 매긴다.

## 6. 레코드 형식 (`ProductSeed`)

```json
{"productId": "p07002", "productName": "무릎 보호대 2개입", "brand": "든든걸음",
 "category": {"main": "silver", "mid": "protector", "sub": "knee-protector"},
 "origin": "국산", "audience": "senior", "isGift": false,
 "pricing": {"price": 16900, "originalPrice": null},
 "spec": {"text": "2개", "quantity": 2, "unit": "개"},
 "delivery": {"isRocket": false, "isFreeShipping": true, "shippingFee": 0, "deliveryDays": 2},
 "stats": {"salesCount30d": 849, "salesCountTotal": 11880, "rating": 4.4, "reviewCount": 1320, "repurchaseRate": 12},
 "content": {"description": "무릎을 감싸 주는 보호대예요. 양쪽 무릎에 하나씩 차요.",
             "reviewSummary": "따뜻하고 흘러내리지 않는다는 평이 많아요.",
             "tags": ["무릎 보호대", "무릎", "보호대", "무릎 아플 때", "관절", "차는 거"]},
 "stock": {"status": "in_stock", "quantity": 130},
 "options": [{"name": "사이즈", "values": [{"value": "M"}, {"value": "L"}, {"value": "XL", "priceAdd": 2000, "stock": "low"}]}],
 "productImage": null, "source": "synthetic"}
```

**쓰지 말 것 (서버가 계산함)**
`discountRate`, `unitPrice`, `priceTier`, `rankInSub`, `rankInMid`, `rankInMain`, `rankOverall`, `badges`,
`arriveLabel`, `arriveSpoken`, `priceSpoken`, 분류 이름(`name`). 넣으면 스키마 검사에서 "모르는 필드"로 실패한다.

**필드 규칙**

| 필드 | 규칙 |
|---|---|
| `productName` | 2~60자. 사람이 부르는 품목명 + 규격. **브랜드·옵션값은 넣지 않는다.** 전체에서 중복 금지 |
| `origin` | 1~20자. 제조국·원산지(국산, 중국, 베트남, 일본, 미국, 독일 …). 식품은 "국산(쌀)"처럼 원료를 밝혀도 된다 |
| `audience` | `senior` / `general` / `kids`. 아래 비율 참고 |
| `isGift` | 선물로 사기 좋으면 true(홍삼·과일 선물세트·안마기·효도폰·완구·그림책 등). 전체의 약 15~25% |
| `pricing.price` | 10원 단위, 현실적인 끝자리(9,900 / 12,500 / 34,900) |
| `pricing.originalPrice` | 할인 전 가격 또는 null. 약 30%의 상품만 쓰고, `price`보다 커야 한다. 할인율 5~30% |
| `spec` | 화면 표기 / 단위 가격용 수량 / 단위(매·개·정·캡슐·포·팩·봉·롤·장·g·kg·ml·L·대·켤레). `"190ml × 24팩"`이면 quantity 24, unit 팩 |
| `delivery` | 로켓 약 50%(배송비 0, 1일) / 무료배송 약 25%(배송비 0, 2~3일) / 유료배송 약 25%(2,500·3,000, 2~4일). 대형 가구·가전은 유료·3~4일이 자연스럽다 |
| `stats.salesCount30d` | 아래 판매 분포 규칙 |
| `stats.salesCountTotal` | `salesCount30d`의 8~30배 |
| `stats.rating` | 소수 첫째 자리. 대부분 4.0~4.9, 중분류마다 3점대 1~2개 |
| `stats.reviewCount` | `salesCountTotal`의 5~15% |
| `stats.repurchaseRate` | 소모품 40~65, 일반 소비재 20~40, 내구재(가전·가구·지팡이·의류) 2~12 |
| `content.description` | 5~120자. **어르신께 말하듯 쉬운 말 1~2문장**, "~예요/~해요"체 |
| `content.reviewSummary` | ≤120자 또는 null. "~다는 평이 많아요" 꼴. 약 80%의 상품에 쓴다 |
| `content.tags` | **6~10개**, 각 1~15자, 중복 금지. 7절 |
| `stock` | `in_stock` 약 90%(21 이상) / `low` 약 7%(1~20) / `sold_out` 약 3%(0) |
| `options` | 4절 |
| `productImage`, `source` | 항상 null, `"synthetic"` |

**audience 비율**
- silver는 거의 전부 senior
- medical·hygiene·health-food는 senior 50~70%
- food·living·kitchen은 general 위주에 senior 20~30%
- kids는 kids 70% 이상. hobby의 큰 글씨 책·퍼즐·컬러링북·서예는 senior
- 나머지는 general 위주. 어르신이 많이 찾는 품목(효도화, 내복, 전기요, 염색약, 등산 스틱, 게이트볼, 좌식 테이블)은 senior

**판매 분포 규칙**
- **중분류마다** 상위 3개가 30일 판매의 40~60%를 차지하는 롱테일로 만든다.
- 1위의 `salesCount30d`: 흔한 생필품 2,000~8,000, 특수품·고가품 30~400
- 싸고 평점 높고 로켓배송인 상품이 대체로 잘 팔린다.

## 7. 태그·표현 규칙

### 태그 (가장 중요) — 6~10개
1. **핵심 품목어.** 짧은 말(3글자 이하)을 하나는 넣는다. 예: `파스`, `쌀`, `김`, `이불`, `냄비`, `양말`, `건전지`.
   검색어와 정확히 같으면 점수를 더 받는다. 없으면 검사기가 경고한다.
2. **용도·증상·상황** 1개 이상: `무릎 아플 때`, `눈 침침`, `겨울에`, `아침에 마실 거`, `밥반찬`
3. **구어·쉬운 말**: `붙이는 거`, `뿌리는 거`, `타 먹는 거`, `혈압 재는 거`, `보청기 약`, `효도폰`
4. **동의어·다른 이름**: `플라스타`, `찜질`, `백미`, `서리태`, `미숫가루`, `전기장판`
5. **특징·대상**: `무가당`, `대용량`, `접이식`, `국산`, `큰 글씨`, `손주 선물`, `부모님 선물`

- 옵션값(색상·사이즈)은 이미 검색 대상이라 태그에 넣지 않아도 된다.
- 선물용 상품(`isGift: true`)에는 `선물`이 들어간 태그를 하나 넣는다.
- 무관한 상품에 인기 낱말을 억지로 붙이지 않는다. 띄어쓰기는 사람이 말하는 대로 쓴다.

### 하지 말 것
- **실제 상표·회사·제품명**을 이름·브랜드·설명·리뷰 요약·태그·옵션 어디에도 쓰지 않는다.
  예: 신신파스, 케토톱, 정관장, 센트룸, 하기스, 디펜드, 오뚜기, 농심, 비비고, 베지밀, 오므론, 쿠쿠, 다이슨, 나이키, 노스페이스, 레고, 바디프랜드.
  `BANNED`(`app/validate.py`)는 일부만 담고 있다. 목록에 없어도 실제 상표면 쓰지 않는다.
- **효능을 단정하는 표현**("관절염 치료", "혈압을 낮춰 줌", "시력 회복", "탈모 치료")을 쓰지 않는다.
  영양제는 "~을 챙기는 분들이 찾는" 정도로 쓰고, 의약품·의료기기는 생활 수준의 사용 장면만 쓴다. 리뷰 요약도 같은 기준이다.
- 어르신을 낮추는 표현, 이모지, 영어 마케팅 문구("BEST", "HOT")를 쓰지 않는다.

## 9. 시연 검색어와 정답

전체 검사(`--main` 없이)를 돌리면, 아래 검색어의 상위 3개와 정답 분류 포함 여부(✓/✗)를 보여 준다.
맡은 대분류에 해당하는 검색어가 ✗이면 태그·이름을 고친다.

| 검색어 | 정답 분류 | 검색어 | 정답 분류 |
|---|---|---|---|
| 무릎 파스 | medical > pain-relief | 효도폰 | silver > easy-device > easy-phone |
| 눈 침침 | medical > eye-care 또는 health-food > eye-joint | 전기요 | digital > seasonal |
| 돋보기 | medical > eye-care | 내복 | fashion > innerwear |
| 아침에 마실 거 | food > drink | 효도화 | fashion-acc > shoes |
| 쌀 | food > rice-grain | 염색약 | beauty > hair |

- 가격·배송·판매·재고 규칙

- 옵션: 값 중복, 추가 금액 범위·단위, 모든 값 품절(오류)
- 거의 같은 이름(경고), 소분류 목표 달성, `BANNED` 단어, 시연 고정 상품, 시연 검색어 정답
